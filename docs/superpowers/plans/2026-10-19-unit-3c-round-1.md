## Review Focus

1. **A session that stops partway, then resumes.** The rows it kept stay
   as they were, the runs it lacked run once, and none runs twice: the
   resumed session must end with the matrix complete (Task 1
   `sessions-resume-where-they-stopped`).
2. **Power lost mid-row.** The torn row is skipped, its run runs again,
   and the new row is whole (Task 1 `resumes-after-a-torn-row`).
3. **Results of another session in `--out`.** A new session must not
   mix its rows in, and a resume must refuse another machine's or
   another commit's session (Task 1 `sessions-refuse-to-mix`).
4. **Other work on the machine.** A busy machine must show in the
   numbers, and a run's own threads must not count as other work (Task
   2 `other-cpu-counts-other-processes`, `other-cpu-leaves-out-the-run`,
   `reports-say-what-else-ran`).
5. **A data directory on tmpfs.** `/tmp` is tmpfs on many desktops,
   robotron among them; the spec requires a real disk, so such a
   session must stop before any run (Task 2
   `sessions-refuse-a-tmpfs-data-directory`).

## Proposals in this plan for Kevin to approve

- **odm runs the round** (decided by Kevin, 2026-10-19, on #3). On
  robotron the 10M random-order runs mostly waited on its encrypted
  disk. odm has 30 virtual CPUs, 188 GB of memory, ext4, and the
  kernel's writeback defaults.
- **Kyoto Cabinet is built from source with Kyoto's own defaults**
  (`-O2 -march=native`), in `~/opt/kyotocabinet-1.2.80` on odm (done:
  the tarball's sha512 matches Arch's PKGBUILD). A distribution's build
  can differ a lot: Arch's 1.2.80-2, robotron's, is compiled at `-O0`,
  because its `--disable-opt` appends `-O0` after the `-O2`. So
  robotron's Kyoto numbers so far, the pilots' and 3b's heads-up
  included, came from an unoptimised Kyoto. The docs say how the
  round's Kyoto was built, and `env.txt` names the programs that ran.
- **A spec correction: tuned Kyoto gets its documented map and page
  cache too** (Task 3). For a database over 64 MB, spex.html advises
  a memory map larger than the database. For TreeDB with abundant RAM,
  it advises a page cache that holds every node, and it recommends
  linear chains once the bucket count is set. The spec's "tuned" took
  only the bucket count. Tuned that way on odm, Kyoto's 10M runs took
  650–1,160 s, mostly reading past its 64 MB map with `pread`. With
  the documented map and cache they took 21–120 s. vivace-cabinet
  always maps its whole file. The correction is a commit on main before
  the branch.
- **The schedule.** About 10 hours for session A (1M) and 6.6
  days for session B (10M): 7 days in all. The estimate takes each
  configuration's 10M set time from the odm pilot, scaled by its 1M
  ratio of the full run to the set phase at each thread count. The
  longest run is the B+ tree's at 10M and 8 threads, about 2 hours.
  Three repeats at 10M instead of the spec's five would take about 4.4
  days. I propose the spec's five: odm runs unattended, and session A's
  report arrives after 10 hours.
- **The per-run timeout is 1 hour in session A and 8 hours in session
  B**, set with `--timeout`: five times the longest 1M run in the
  pilot, and about four times the longest 10M estimate. The default (10
  minutes plus 1 ms a record: 10,600 s at 10M) is shorter than some 10M
  runs take.
- **A session on odm executes the whole plan** (Kevin, 2026-10-19), so
  the round does not depend on robotron. The round takes days: a
  session that ends while a unit runs is fine, and the next one resumes
  from the ledger (Task 4, Step 3).
- **Two harness additions** (Tasks 1 and 2).
  - `--resume` continues a session in `--out`, and `--report-only`
    writes a report from `--out` alone.
  - Each run records its wall seconds and the CPU seconds the rest of
    the machine used meanwhile, from `/proc/stat`. That covers odm's
    services, and its Xen neighbours through steal time. The review of
    3b suggested the load average at each run's start, but that would
    mostly show the previous run's own threads.
  - `env.txt` names the CPU's frequency governor (none on a Xen
    guest), the kernel's writeback limits (the pilots showed they
    matter), and the Kyoto programs that ran. A data directory on tmpfs
    is refused, and the disks line loses lsblk's padding.
- **The code is reviewed before the run, not after.** A fresh review of
  Tasks 1 to 3, and its fix pass, come between Task 3 and Task 4: a fix
  found after the run would mean running it again. This is a gate I am
  adding.
- **Where the results go.** `bench/results/round-1-odm/` (`runs.csv`,
  `sizes.csv`, `env.txt`, `failures.log` if any run failed) and
  `docs/benchmarks/round-1.md`, both committed.
- **A page of observations**, `docs/benchmarks/round-1-notes.md`,
  written by hand after the run, under a page. It covers what rows 1
  and 2 say about reaching Kyoto through FFI, how vivace-cabinet's
  engines compare with Kyoto's (rows 2 to 5), and what that suggests
  for vivace-graph's storage. The report itself stays generated.

(defun small-matrix (out data &rest args)
  "Kyoto's own hash program at 200 records, two orders, one and two
threads, two repeats: two size rows and eight run rows into OUT."
  (apply #'run-matrix :engines '(:kyoto-hash-native) :ns '(200)
                      :threads '(1 2) :orders '(:sequential :random)
                      :tunings '(:default) :repeats 2 :data data :out out
                      args))

(defun keep-lines (path n)
  "Cut the file PATH to its first N lines, as a killed session leaves it."
  (let ((lines (subseq (uiop:read-file-lines path) 0 n)))
    (with-open-file (s path :direction :output :if-exists :supersede)
      (format s "~{~a~%~}" lines))))

(defun set-environment-line (path name value)
  "Rewrite the env.txt line NAME of PATH to VALUE."
  (let ((lines (mapcar (lambda (l)
                         (if (uiop:string-prefix-p (format nil "~a:" name) l)
                             (format nil "~a: ~a" name value)
                             l))
                       (uiop:read-file-lines path))))
    (with-open-file (s path :direction :output :if-exists :supersede)
      (format s "~{~a~%~}" lines))))

(fiveam:test sessions-resume-where-they-stopped
  "A resumed session keeps the rows it finds and runs only the rest."
  (with-scratch (dir)
    (let* ((out (merge-pathnames "out/" dir))
           (data (merge-pathnames "data/" dir))
           (csv (merge-pathnames "runs.csv" out))
           (sizes (merge-pathnames "sizes.csv" out)))
      (small-matrix out data)
      (keep-lines csv 6)
      (keep-lines sizes 2)
      (let ((kept (uiop:read-file-lines csv)))
        (small-matrix out data :resume t)
        (let ((lines (uiop:read-file-lines csv)))
          (fiveam:is (equal kept (subseq lines 0 6)))
          (fiveam:is (= 9 (length lines)))
          (fiveam:is (= 8 (length (remove-duplicates
                                   (mapcar #'run-key (read-runs csv))
                                   :test #'equal)))))
        (fiveam:is (= 2 (length (read-runs sizes))))
        (fiveam:is-true (search "resumed: " (uiop:read-file-string
                                             (merge-pathnames "env.txt"
                                                              out))))))))

(fiveam:test resumes-after-a-torn-row

session resumes, and its new row is whole."

    (let* ((out (merge-pathnames "out/" dir))

(fiveam:test sessions-refuse-to-mix
  "A session will not add rows to another's results unless resuming it,
nor resume one from another machine or commit."
  (with-scratch (dir)
    (let* ((out (merge-pathnames "out/" dir))
           (data (merge-pathnames "data/" dir))
           (csv (merge-pathnames "runs.csv" out))
           (env (merge-pathnames "env.txt" out)))
      (small-matrix out data)
      (let ((before (uiop:read-file-string csv)))
        (fiveam:signals error (small-matrix out data))
        (set-environment-line env "vivace-cabinet" "0000000")
        (fiveam:signals error (small-matrix out data :resume t))
        (set-environment-line env "vivace-cabinet"
                              (cdr (assoc "vivace-cabinet" (environment data)
                                          :test #'string=)))

        (fiveam:is-true (probe-file report))
        (fiveam:is (string= rows (uiop:read-file-string csv))))
      (fiveam:signals error (main :report-only t :report report))
      (fiveam:signals error (apply #'main :resume t (cddr args))))))

(defun burner (seconds)
  "A python3 command line that keeps one hardware thread busy for
SECONDS of wall time."
  (format nil "python3 -c 'import time; t = time.time(); ~
any(iter(lambda: time.time() - t > ~a, True))'" seconds))

(fiveam:test other-cpu-counts-other-processes
  "CPU that other processes use while a run runs is its :OTHER-CPU."
  (with-scratch (dir)
    (let ((burn (uiop:launch-program (burner 3))))
      (unwind-protect
           (let ((m (nth-value 1 (measured (list "sleep" "2.5")
                                           (merge-pathnames "measure.out"
                                                            dir)))))
             (fiveam:is (>= (getf m :other-cpu) 2.0) "~s" m))
        (uiop:wait-process burn)))))

(fiveam:test other-cpu-leaves-out-the-run
  "A run's own CPU, its children's included, is not in :OTHER-CPU.  Its
sixteen burners outweigh other work on a machine of 4 or 30 threads."
  (with-scratch (dir)
    (let ((m (nth-value 1 (measured
                           (list "sh" "-c"
                                 (format nil "~{~a & ~}wait"
                                         (make-list 16 :initial-element
                                                       (burner 2.5))))
                           (merge-pathnames "measure.out" dir)))))
      (fiveam:is (>= (+ (getf m :user) (getf m :system)) 4.0) "~s" m)
      (fiveam:is (< (getf m :other-cpu) (+ (getf m :user) (getf m :system)))
                 "~s" m))))

(fiveam:test runs-record-what-else-ran
  "Each row has the run's wall seconds and the other processes' CPU."
  (with-scratch (dir)
    (let* ((out (merge-pathnames "out/" dir))
           (rows (progn (small-matrix out (merge-pathnames "data/" dir))
                        (read-runs (merge-pathnames "runs.csv" out)))))
      (fiveam:is (every (lambda (r) (and (realp (getf r :wall))
                                         (realp (getf r :other-cpu))))
                        rows)
                 "~s" (first rows)))))

(fiveam:test reports-say-what-else-ran

its median over the runs and its most in one run."

                                  :tuning :default :order :sequential
                                  :n 1000 :threads 1 :repeat repeat
                                  :open 0.1 :set 0.1 :get 0.1 :remove 0.1
                                  :close 0.1 :wall 10 :cpu 0.5
                                  :other-cpu other :rss-kb 1024
                                  :count 1000 :left 0 :errors 0 :exit 0)
                          *columns*)))
    (with-open-file (s (merge-pathnames "env.txt" dir) :direction :output)
      (format s "machine: m~%"))
    (let ((text (uiop:read-file-string (write-report dir))))
      (fiveam:is (search (format nil "a median of 20% of one hardware ~
thread, and at most 50%") text)
                 "~a" text))))
